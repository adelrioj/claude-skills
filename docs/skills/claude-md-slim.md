# `/claude-md-slim`

Makes the root `CLAUDE.md` minimal by keeping only **session-invariant rules** always-on and **moving** everything else (per-skill/subsystem detail, long rationale, edge-case enumerations) to `docs/<topic>.md` behind one-line **plain-path pointers**. The deliberate inverse of `claude-md-improver`: that skill's gradient is *completeness* (adds), this one's is *minimal always-on context* (extracts) — so it's a separate skill, not a mode. Motivated by *"Less Context, Better Agents"* (arXiv:2606.10209): less always-on context with detail retrieved on demand is both cheaper and more reliable, and `CLAUDE.md` loads into every session. The load-time lever is that pointers must be **plain paths, never `@`-imports** — an `@`-import stays eagerly expanded at load and only reorganizes without cutting the token bill. A **fixer** (unlike the report-only `/architect-review-pr`, `/blind-spot`): it edits files, so it **confirms the triage plan before applying** and **moves-never-deletes** (no information lost; root shrinks, detail becomes reachable-on-demand). Verifies the win with `wc -lc` before/after; leaves everything uncommitted. No external CLI — installs anywhere.

## Conventions

- `/claude-md-slim` is the deliberate INVERSE of `claude-md-improver` (completeness/adds) — it cuts always-on size by extracting non-invariant blocks to `docs/`; kept a separate skill because opposite gradients in one skill fight each other
- `/claude-md-slim` pointers are **plain paths, never `@`-imports** — an `@`-import stays eagerly expanded at load, so it reorganizes without reducing the always-on token bill and defeats the skill's entire purpose (the load-time distinction is the skill's core lever)
- `/claude-md-slim` **moves, never deletes** — every paged-out block lands verbatim in a `docs/` file (no-data-loss is non-negotiable; it's a reorganizer, not a trimmer) — and it **confirms the triage plan before applying** since `CLAUDE.md` is the user's project memory; edits left uncommitted, win verified via `wc -lc` before/after
- `/claude-md-slim`'s triage line: STAYS always-on = rules true for EVERY task (safety, build/test/lint/run commands, commit/branch gates, one-line orientation, the pointer index); PAGES OUT = area-specific detail only needed when touching that subsystem; tie-breaker is page-out (a missed pointer costs one on-demand read, a kept paragraph costs every session forever)
