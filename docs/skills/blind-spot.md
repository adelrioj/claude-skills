# `/blind-spot`

Pre-implementation pass that surfaces the **unknown-unknowns of a task you're about to start** — the mirror image of `/architect-review-pr`, which reviews a finished diff for wiring gaps; this reviews a *forthcoming task* for what you can't see about the codebase, the domain, and the decisions ahead. Dispatches ONE fresh-context Claude `Agent` subagent (no `codex` dependency — installs anywhere) that hunts across a fixed taxonomy behind a mandatory **evidence gate**, calibrated to a parsed experience signal so it neither lectures on what you already know nor assumes expertise you don't have. Findings are ranked by **impact on the decisions ahead**, above finding type — the point is surfacing unknowns whose answers change the architecture. Closes with a **sharpened brief**: 2–4 sentences you can paste to start the real work with the top unknowns pre-resolved or explicitly deferred. **Report-only** — a finder, never a fixer; the subagent writes the ranked report itself to a path resolved once before dispatch, the main loop reads that exact path, and it STOPs. A git repo is NOT required: a pure-domain pass runs with no repo at all. The only blocking question is "what are you about to work on?" when the invocation names no task.

## Conventions

- `/blind-spot` runs BEFORE work starts; `/architect-review-pr` runs after it finishes. Opposite ends of the same axis, and neither substitutes for the other. It is also not `/brainstorming` — brainstorming decides *what to build* through dialogue, blind-spot surfaces *what you can't see* about a task already chosen, in one shot. They compose: blind-spot → then brainstorm the resolved scope
- `/blind-spot` is report-only — it never edits code, writes a plan, or starts the work; feed its output to `/writing-plans` or your next prompt (contrast the spec-review family, which fix-loops)
- `/blind-spot` uses a Claude `Agent` subagent, not `codex` — deliberately no external CLI dependency. The subagent is read-only (Grep, Read, WebSearch, WebFetch) with exactly one carve-out: it `Write`s its own report to `<REPORT_PATH>`, incrementally, and returns the same markdown only as corroboration
- **The report path is resolved once, before dispatch, and passed in** — `REPORT_PATH="${TMPDIR:-/tmp}/blind-spot-$(date +%s).md"`, held in a variable and substituted into the prompt. The main loop reads that exact variable. It must **never** glob `blind-spot-*.md`, and must never write the report from the subagent's return message: a subagent that completes its pass then idles sends no final message, so writing "what was received" yields no report at all, while globbing silently adopts a stale report from an earlier pass on a *different* task. Missing file ⇒ say so and stop; never re-dispatch or re-ask (a re-ask has never recovered a lost hand-off). Same rationale as ship-it's contract-as-file, and the pattern `review-codebase` uses
- `/blind-spot` requires a described task but **not** a git repo — a pure-domain pass ("I don't know what color grading is") is valid with no repo, and not gating on one keeps that case in scope. The single blocking question is what the task is; experience level is optional and defaults to *"unstated — assume working proficiency, calibrate conservatively, ask nothing"*
- `/blind-spot` ranks by **impact on the decisions ahead** as the primary sort, ABOVE taxonomy type — an unknown that changes the architecture outranks a more exotic one that doesn't. Every codebase finding cites a grep/read; every domain finding is marked `[external knowledge]` with a source. A finding with no citation is downgraded to a question, not reported as a finding
- `/blind-spot` offers an HTML briefing via the **Artifact** tool only if the user says yes — never rendered automatically (load `artifact-design` first if building one)
- One subagent, not a panel; upgrade path is one subagent per axis (domain vs codebase) merged, only if single-agent recall proves insufficient. The "interview me" follow-up stays a hand-written cheat-sheet prompt rather than folding in `/brainstorming`'s dialogue machinery
- Origins: synthesizes Thariq's *"A Field Guide to Fable: Finding Your Unknowns"* (the blind-spot pass and the known/unknown quadrant model) and Diego Marino's *Fable adversarial audits* gist (adversarial framing + evidence-gated, ID'd, impact-ranked findings) — the same gist `/review-codebase` draws its three audit templates from. Only the blind-spot pass ships as a skill; the field guide's other techniques are not bundled
