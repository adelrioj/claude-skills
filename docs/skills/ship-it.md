# `/ship-it`

Pure conductor that chains the existing units into one autonomous spec→PR pipeline. Seven-step sequential process: hardens the spec via `/spec-review-codex`, writes the implementation plan, executes it via `/plan-to-dex`, opens a PR with `/commit-commands:commit-push-pr`, then a `general-purpose` subagent runs the whole `/review-pr` panel and applies the CRITICAL/IMPORTANT fixes to the working tree — the built-in `/code-review` is `disable-model-invocation` and can't be called autonomously, so `/review-pr` (no such flag) is run inside the subagent instead (up to 3 review passes, conductor commits/pushes between them), then closes with a report-only `/architect-review-pr` completeness pass whose findings land in the final report; merging stays manual. A preflight (codex + dex on PATH, `pr-review-toolkit` and `commit-commands` plugins present via on-disk command-file checks, spec located) is the sole hard abort. The heavy steps (1/2/4/6) run as **subagents** that return only a structured three-field contract, keeping raw codex/dex/review output out of the conductor's context; Steps 3/5/7 run in the main loop, and Step 6's commit/push fix loop is driven by the conductor around its per-pass review-and-fix subagent. Never halts on quality findings; records any leftover issues in a final report. Requires the `codex` and `dex` CLIs plus the `pr-review-toolkit` and `commit-commands` plugins.

## Conventions

- `/ship-it` is a pure conductor — it invokes spec-review-codex, writing-plans, plan-to-dex, /commit-commands:commit-push-pr, and architect-review-pr LIVE and duplicates none of their logic; Step 6's subagent runs the `/review-pr` panel LIVE (not the built-in `/code-review`, which can't be model-invoked)
- `/ship-it`'s Step 6 gives the review-and-fix subagent the PR number as the review target — after the push, the branch's default review range (`@{upstream}...HEAD`) is empty — and the subagent runs `/review-pr` then applies the CRITICAL/IMPORTANT fixes to the working tree without committing; the conductor commits, pushes, and re-dispatches. `/review-pr` launches analyzers via the `Task` tool, so if the harness forbids a subagent spawning subagents the Step 6 subagent runs the review aspects inline instead
- `/ship-it` is best-effort and never halts on quality; the only hard abort is a failed preflight; a hard failure that makes the next step impossible skips downstream steps and jumps to the final report — it never fabricates a downstream artifact (no empty PR)
- `/ship-it` keeps no state on disk except the final report, which is written /handoff-style to the OS temp dir, never the workspace
- `/ship-it` runs the heavy steps (1/2/4/6) as subagents that return only a three-field contract (outcome/state/notes), keeping raw codex/dex/review output out of the conductor's context; Steps 3/5/7 run in the main loop, and Step 6's commit/push fix loop wraps its per-pass review-and-fix subagent. The zero-diff check is always verified against git in the conductor's own shell, never from a subagent summary, so a mis-summary can't fabricate a PR
- `/ship-it`'s Step 7 (architect-review-pr) is record-only — the conductor never fixes architect findings, it puts them in the final report; and since architect-review-pr reviews the branch diff (not the PR object), a failed PR creation skips only Step 6, while a zero diff from Step 4 skips Steps 5-7
