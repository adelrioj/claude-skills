# `/ship-it`

Pure conductor that chains the existing units into one autonomous spec→PR pipeline. Seven-step sequential process: hardens the spec via `/spec-review-codex`, writes the implementation plan, executes it via `/plan-to-dex`, opens a PR with `/commit-commands:commit-push-pr`, then a `general-purpose` subagent runs the whole `/review-pr` panel and applies the CRITICAL/IMPORTANT fixes to the working tree — the built-in `/code-review` is `disable-model-invocation` and can't be called autonomously, so `/review-pr` (no such flag) is run inside the subagent instead (up to 3 review passes, conductor commits/pushes between them), then closes with a report-only `/architect-review-pr` completeness pass whose findings land in the final report; merging stays manual. A preflight (codex + dex on PATH, `pr-review-toolkit` and `commit-commands` plugins present via on-disk command-file checks, spec located) is the sole hard abort. The heavy steps (1/2/4/6) run as **subagents** that deliver a structured three-field contract by **writing it to a conductor-supplied path in `$RUN_DIR`** (a `mktemp -d` minted at preflight), keeping raw codex/dex/review output out of the conductor's context; Steps 3/5/7 run in the main loop, and Step 6's commit/push fix loop is driven by the conductor around its per-pass review-and-fix subagent. Never halts on quality findings; records any leftover issues in a final report. Requires the `codex` and `dex` CLIs plus the `pr-review-toolkit` and `commit-commands` plugins.

## Conventions

- `/ship-it` is a pure conductor — it invokes spec-review-codex, writing-plans, plan-to-dex, /commit-commands:commit-push-pr, and architect-review-pr LIVE and duplicates none of their logic; Step 6's subagent runs the `/review-pr` panel LIVE (not the built-in `/code-review`, which can't be model-invoked)
- `/ship-it`'s Step 6 gives the review-and-fix subagent the PR number as the review target — after the push, the branch's default review range (`@{upstream}...HEAD`) is empty — and the subagent runs `/review-pr` then applies the CRITICAL/IMPORTANT fixes to the working tree without committing; the conductor commits, pushes, and re-dispatches. `/review-pr` launches analyzers via the `Task` tool, so if the harness forbids a subagent spawning subagents the Step 6 subagent runs the review aspects inline instead
- `/ship-it` is best-effort and never halts on quality; the only hard abort is a failed preflight; a hard failure that makes the next step impossible skips downstream steps and jumps to the final report — it never fabricates a downstream artifact (no empty PR)
- `/ship-it` keeps no state in the workspace; everything it persists lives in `$RUN_DIR` (`mktemp -d`, minted and printed at preflight): each step's contract, Step 7's architect report, and the /handoff-style final report
- `/ship-it` runs the heavy steps (1/2/4/6) as subagents that deliver a three-field contract (outcome/state/notes) **as a file** at a path the conductor fixes up front and passes in, keeping raw codex/dex/review output out of the conductor's context; Steps 3/5/7 run in the main loop, and Step 6's commit/push fix loop wraps its per-pass review-and-fix subagent
- **A subagent's final message is a single-delivery, unrecoverable channel** — observed runs had 5/5 and 4/5 subagents complete their work and end with a bare `idle_notification` and no contract, and a `SendMessage` re-ask recovered none. So the contract file is the carrier and the return message is corroboration; subagents are told to write the file **incrementally** (outcome/state early, notes appended as findings land) so it survives an agent that idles mid-work, not just one that idles at the end
- Every step also has a **ground-truth predicate** the conductor checks in its own shell — a findings file newer than dispatch (1), `test -f <plan>` (2), `git status --porcelain` or `HEAD` moved off the pre-dispatch SHA (4), `git status --porcelain` non-empty ⇒ fixes applied (6), `test -f` the architect report (7). Two rules keep these honest: **anchor every predicate to a value captured before dispatch** (an mtime, a commit SHA) — an unanchored `ls`/`git log` check is satisfied by a previous run's artifact, which is the stale-artifact bug wearing a different hat — and **prove the step RAN, not that it CHANGED something**, since a spec review that passes on iteration 1 rewrites nothing and that best-case outcome must not read as failure. Git is the authority, the contract is the narrative: a missing contract with work on disk is `finished-with-notes (contract lost — state reconstructed from git)` and the run continues; only "no contract AND no work" changes control flow. The conductor **never** re-asks, polls `TaskOutput`, or re-dispatches — the work completed, only reporting failed
- **No artifact is ever located by glob.** Contract, architect report and final report paths are all fixed at preflight, because a timestamped pattern like `architect-review-pr-*.md` is satisfied by a stale report from a previous session on a different ticket — silently adopting one is worse than having none. The final report names any step whose contract was lost or disagreed with its predicate, so a lossy run can't read as a clean one
- `/ship-it`'s Step 7 (architect-review-pr) is record-only — the conductor never fixes architect findings, it puts them in the final report; and since architect-review-pr reviews the branch diff (not the PR object), a failed PR creation skips only Step 6, while a zero diff from Step 4 skips Steps 5-7
