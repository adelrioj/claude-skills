# `/ship-it`

Pure conductor that chains the existing units into one autonomous spec→PR pipeline. Seven-step sequential process: hardens the spec via `/spec-review-codex`, writes the implementation plan, executes it via `/plan-to-dex`, opens a PR with `/commit-commands:commit-push-pr`, runs the built-in `/code-review high --fix <PR#>` which applies its own verified findings (up to 3 review passes, conductor commits/pushes between them), then closes with a report-only `/architect-review-pr` completeness pass whose findings land in the final report; merging stays manual. A preflight (codex + dex on PATH, `commit-commands` plugin present via an on-disk command-file check, spec located) is the sole hard abort. The heavy Skill steps (1/2/4) run as **execute-and-report subagents** that return only a structured three-field contract, keeping raw codex/dex output out of the conductor's context; Steps 3/5/6/7 run in the main loop, with one boundary-verifier subagent after PR-review. Never halts on quality findings; records any leftover issues in a final report. Requires the `codex` and `dex` CLIs plus the `commit-commands` plugin.

## Conventions

- `/ship-it` is a pure conductor — it invokes spec-review-codex, writing-plans, plan-to-dex, /commit-commands:commit-push-pr, the built-in code-review skill, and architect-review-pr LIVE and duplicates none of their logic
- `/ship-it`'s Step 6 passes the PR number as the review target — after the push, the branch's default review range (`@{upstream}...HEAD`) is empty — and uses `--fix` so the review applies its own verified findings; the conductor only commits, pushes, and re-reviews
- `/ship-it` is best-effort and never halts on quality; the only hard abort is a failed preflight; a hard failure that makes the next step impossible skips downstream steps and jumps to the final report — it never fabricates a downstream artifact (no empty PR)
- `/ship-it` keeps no state on disk except the final report, which is written /handoff-style to the OS temp dir, never the workspace
- `/ship-it` runs the heavy Skill steps (1/2/4) as execute-and-report subagents that return only a three-field contract (outcome/state/notes), keeping raw codex/dex output out of the conductor's context; Steps 3/5/6/7 run in the main loop. The zero-diff check is always verified against git in the conductor's own shell, never from a subagent summary, so a mis-summary can't fabricate a PR
- `/ship-it`'s Step 7 (architect-review-pr) is record-only — the conductor never fixes architect findings, it puts them in the final report; and since architect-review-pr reviews the branch diff (not the PR object), a failed PR creation skips only Step 6, while a zero diff from Step 4 skips Steps 5-7
